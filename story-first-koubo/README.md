# 故事型口播：说说我的体会

一个用于个人成长类真人口播的个人技能。用视频记录所学所感，给遇到相似问题的人一点参考。

线上位置：[Gaobo2882/gaobo-skills · story-first-koubo](https://github.com/Gaobo2882/gaobo-skills/tree/master/story-first-koubo)。用户已授权公开保存，后续持续更新此目录。

## 表达定位

- 像随手拿出手机和朋友聊一件事，真诚、轻松、有趣。
- 多用真实故事、具体场景和个人体会，不站在高处教育别人。
- 保留真实态度和直接判断，不把“不说教”写成一味温和。有本人原稿时先做轻编辑，故事可短，观点可以直接讲。
- 选题不固定：学习、心态、工作、阅读、人际关系与日常观察都可以讲。
- 可以引用核实过的书籍、人物和研究，但不堆知识、不装权威。
- 记录与分享优先，点赞、转发、涨粉和营销不是主要目标。

本次更新：保留各点核心方法，用具体收益和小行动展开；减少重复铺垫，区分表达力度与事实准确性。

## 文件

- `SKILL.md`：完整写作与审稿规则，当前版本 0.1.6。
- `agents/openai.yaml`：技能名称和调用入口。
- `AGENTS.md`：修改、验证和同步仓库的约定。

## 使用

从合集仓库取出 `story-first-koubo` 文件夹，放到 Codex 的个人技能目录。该文件夹下直接包含 `SKILL.md`，不要把整个合集仓库当成一个技能安装。

可以这样说：

> 用 $story-first-koubo，把下面的经历写成一篇自然的口播稿，像散步时聊天，不要说教。

> 用 $story-first-koubo，看看这篇稿子哪里绕、哪里太像讲课，先评审，不重写。

## 怎么迭代

从实际写稿和录制反馈中改进：哪里念着不顺、哪里不像自己的话、哪个地方过于正式，都可以成为下一次调整的依据。区分当前稿件的临时要求与长期表达偏好；已认可的稿件才作为风格样本。

每次明确要求更新技能后，在同一次任务中修改本地文件、完成检查、记录 Git 提交、同步到 GitHub，并核验远端结果；这些步骤都完成后才报告更新成功。同步受阻时明确标记“本地已改，线上未同步”。这个约定不代表存在后台自动监控或文件监听。

后续可按需要增加选题搜寻、阅读素材整理、录制辅助等能力。目前这些是方向，尚未实现，不预先添加空的技能或复杂框架。

方法参考链接见 `SKILL.md`。
