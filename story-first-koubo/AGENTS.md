# 仓库维护约定

## 范围

这个仓库维护用户自己的“故事型口播”技能。表达定位以 `SKILL.md` 和用户最新明确反馈为准。不要把某篇未确认的初稿写成长期偏好或自动上传私人稿件、录音、聊天记录。

用户于 2026 年 9 月 27 日明确授权公开上传。固定同步目标为 `Gaobo2882/gaobo-skills`，分支 `master`，目录 `story-first-koubo/`。这取代此前未落地的私有仓库方案。只上传技能规则和维护说明，不上传私人稿件、录音或聊天记录。

## 修改与同步

- 用户已要求把此技能保存在自己的 GitHub 仓库，并在后续明确修改技能时同步。完成对应修改后，可在上述仓库和目录内公开提交与上传，无需每次重复申请。
- 先查看本地状态与远端最新内容，保护用户和其他任务的改动。只提交本次相关文件；不强推，不用旧本地内容覆盖远端更新。
- 对有效的规则变化更新 `SKILL.md` 中的版本，并保持 README 的版本说明一致。提交说明简述具体改变和原因。
- 使用可用的 skill-creator 校验器检查技能格式，并人工核对规则与用户目标是否一致。文稿质量需要实际使用反馈，格式通过不等于写作效果已验证。
- 本地支持 Git 认证时正常提交、推送；只有连接器能写入时，可用 GitHub 文件或 Git 对象接口提交。上传前核验目标、分支及最新版本，上传后回读文件或提交结果确认成功。
- 当前本地 Git 根目录仅包含本技能，远端则是多技能合集，二者根目录结构不同。不得把本地分支直接推送覆盖远端；使用连接器按 `story-first-koubo/` 路径映射，基于远端最新提交更新，保留其他技能。若改用 Git 推送，应另行克隆合集并仅复制本技能到对应子目录。
- 用户要求每次技能更新同步线上：在同一次修改任务中完成验证、提交、上传与远端核验，才可报告更新已完成。仅本地保存时须明确标记“本地已改，线上未同步”。此要求不等于已建立后台文件监听。
- 若上传失败，保留本地改动，明确说明未同步及所需动作。不要承诺未配置的定时监控或自动后台更新。
- 每次交付提供已验证的线上技能链接或提交链接；不能把本地提交当作上传成功。

## 扩展

先把口播稿写作做好。用户后续要求新增选题、素材研究或录制辅助时，再根据实际用途决定拆为独立技能还是加入简短规则；不先建空目录，不扩大到发布或营销。
